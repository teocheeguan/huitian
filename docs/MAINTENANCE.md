# 惠田库存项目维护交接

## 当前基线

上线基线部署在现有 Ubuntu 和 Nginx 环境中，用 HTTPS 的 `/huitian/` 子路径提供入口，由独立 systemd 服务运行。上线时验证了登录页、静态资源、未登录 API 拦截和开机自启，且接入前后的主站首页内容及域名跳转一致。公开仓库采用示例域名，生产访问地址和服务器登录由公司内部提供。

日常流程由订单管理、商品管理、库存管理、进销管理、调货管理、基础设置和运营看板组成。生产升级用 SQLite 迁移保留商品编号及业务历史，新增匿名订单桶账与瓶装水、其他类目。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `app.py` | 启动命令、账号、登录会话、HTTP 路由、鉴权、事务边界和 SQLite 备份 |
| `inventory.py` | 基础档案、单据校验、库存与桶账计算、防重复记账、冲销 |
| `schema.sql` | 表结构、唯一约束和流水保护触发器 |
| `reports.py` | 门店可见范围、库存、单据、客户桶账和总部看板 |
| `importing.py` | CSV 和 XLSX 期初导入、逐行校验和重复导入识别 |
| `web/` | 原生浏览器页面、样式、表单和相对路径 API 调用 |
| `test_inventory.py` | 使用临时数据库的核心业务和 HTTP 回归测试 |
| `deployment/` | systemd、Nginx 示例及部署和回滚流程 |

## 容易混淆的业务规则

- **订单与库存**。门店订单复用销售单据。一次确认同时记录商品扣减、桶装水送出和实收空桶；进货只增加分配门店的商品库存。门店账号只能对本店下单。
- **空桶类型**。同品牌、同规格才抵扣应回桶。其他桶型按实收分别增加库存。看板按北京时间的业务日期从流水汇总，跨日自动显示当天，往日可查询。
- **商品删除与历史**。零库存商品可从目录删除，底层编号和流水保留。存量销售单仍可从原单处理补送、退货或冲销。旧客户、押桶及期初记录保留在原账套，日常页面和接口移除了对应的新增入口。
- **调拨、盘点和冲销**。调拨在同一事务更新两店。盘点填实盘数。已确认单据保留，纠错用关联冲销单并填写原因。

## 维护流程

1. 克隆仓库，做功能修改时从最新 `main` 开分支。用演示数据复现，并运行 `python3 -B -m unittest -v`。
2. 通过 Pull Request 说明影响的业务规则、测试结果，以及数据库变更是否兼容旧库。发布前标记待上线的提交。
3. 获授权后按 [部署和回滚](../deployment/DEPLOY.md) 更新。备份业务数据库，核对线上服务使用的路径和启动参数，然后验证登录页、库存 API 的登录要求和原站点首页响应。
4. 遇到异常时记录版本、操作入口、可公开的错误文字和最短复现步骤，以便跨电脑或交给其他 AI 工具继续。示例客户和订单使用合成数据。

目前没有连接 GitHub 触发自动生产部署。新增协作者由仓库管理员按 GitHub 账号授权。
